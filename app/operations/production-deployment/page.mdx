# Production Deployment

## Environment Roles

- Development and build host: `mds-internal` by default, with source under
  `/data/coding/maitask`; use `mds-nebula` when its private alias is reachable.
- Production Plane and console host: `uldsa` by default, with deployment state
  under `/data/maitask`; use `uldsa-nebula` only after verifying connectivity.
- Public hosts: `maitask.com` for the console and `api.maitask.com` for Plane.
- Managed Runtime nodes: `runtime-uldsa`, `runtime-eds`, `runtime-uslab`, and
  `runtime-kr1012`.

Do not build source on production or Runtime worker nodes. Plane and Plane
Frontend use production container images; managed Runtime workers use signed
native binaries only. All managed production Runtime nodes consume the default
`shared` queue unless an execution explicitly targets another pool.

## Plane And Frontend

Run from `/data/coding/maitask` on the build host after both repositories are
committed and clean:

```bash
scripts/deploy-production-stack.sh --production-host uldsa
```

The script builds and validates both images, validates the Cloudflare Worker
build, transfers the images, updates production image settings, restarts only
Plane and Frontend, and runs internal and public smoke checks. Runtime is not
part of this container deployment.

## Runtime Release

Build and sign the native artifact on the build host:

```bash
cd /data/coding/maitask/runtime
RUNTIME_RELEASE_GLIBC_BASELINE=2.31 \
RUNTIME_RELEASE_SIGNING_KEY=/data/maitask/secrets/runtime-release.ed25519 \
RUNTIME_RELEASE_SIGNER_NAME='Maitask Release' \
scripts/build-release.sh --target x86_64-unknown-linux-gnu
```

The private signing key remains on the build host. Transfer only the release
archive and signature metadata to the canonical production store:

```text
/data/maitask/releases/runtime-artifacts
```

Keep that directory limited to active Plane-registered artifacts and their
signature metadata. Register the artifact through Plane with its version,
target triple, size, compression, SHA-256 digest, signature, and release notes.
Plane owns the authenticated download URL under
`https://api.maitask.com/runtime/artifacts/<artifact-id>/download`; do not add a
separate public Runtime artifact server or copy source to worker nodes.

## Runtime Rollout

1. Create a Plane rollout for the selected Runtime IDs.
2. Confirm every target is drained and has zero active executions.
3. Runtime downloads the assigned artifact and verifies its size, SHA-256
   digest, Ed25519 signature, target triple, and archive structure.
4. Runtime stages the binary atomically, retains the configured backups, and
   restarts through its configured supervisor.
5. The restarted process reports completion to Plane and removes staging data.

A completed rollout requires:

- rollout status `completed`
- every target status `succeeded`
- every managed node on the released version
- node status and desired status both `online`
- `node_pool=shared` and zero active executions
- `maitask-runtime.service` active on every host

Do not manually replace a Runtime binary or bypass signature verification.
Rollback uses a new Plane rollout targeting a previous signed artifact.

## Production Release Gate

Run from `plane/` on the build host after repository-local checks have passed:

```bash
PACKAGE_MATRIX_HTTP_TARGET_URL=http://172.23.22.30:18881/.well-known/maitask/package-regression/health \
scripts/release-gate.sh \
  --base-url https://api.maitask.com \
  --internal-health-url https://api.maitask.com/health \
  --failover-env-ssh uldsa:/data/maitask/.env \
  --cleanup-db-ssh uldsa:/data/maitask \
  --skip-local
```

The gate covers Plane API regression, Runtime lease failover, the complete
official package matrix using controlled fixtures, backup verification, and
production regression cleanup. Live third-party checks remain optional
diagnostics.

## Final Verification

```bash
curl -fsS https://maitask.com/ >/dev/null
curl -fsS https://api.maitask.com/health >/dev/null
curl -sS -o /dev/null -w '%{http_code} %{redirect_url}\n' https://www.maitask.com/
curl -sS -o /dev/null -w '%{http_code}\n' https://api.maitask.com/runtime/nodes
ssh uldsa 'cd /data/maitask && docker compose ps'
```

Expected results are frontend HTTP 200, `www` HTTP 301 to `maitask.com`, healthy
Plane dependencies, HTTP 401 for the unauthenticated protected API, and healthy
production Compose services. Verify each Runtime host separately with:

```bash
sudo systemctl is-active maitask-runtime.service
sudo -u maitask /var/lib/maitask/runtime/bin/maitask-runtime --version
```

Before handoff, the regression cleanup dry-run must report zero users,
executions, packages, workflows, sessions, and Runtime probe nodes.
