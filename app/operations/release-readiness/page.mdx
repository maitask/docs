# Release Readiness

Release readiness is established from current source, repository gates, the
target environment, and a verified backup. Do not use historical validation
results as evidence for a new release.

## Repository Gates

Run the gates for every changed component.

### Plane

```bash
cargo fmt --check
cargo check --locked --all-targets
cargo test --locked --all-targets
```

### Plane Frontend

```bash
npm run lint
npm run type-check
npm run build
```

### Runtime

```bash
cargo fmt --check
cargo check --locked --all-targets
cargo check --locked --all-targets --no-default-features
cargo test --locked --all-targets
```

### Packages And Docs

Run package-specific tests or archive smoke checks for changed packages. For the
documentation site:

```bash
npm run typecheck
npm run build
```

## Environment Gate

- Repositories are committed and clean on the build host.
- Plane, Frontend, Runtime, and package contracts agree.
- Operational policy is persisted through Plane settings and admin API/UI.
- Secrets, host paths, and endpoints are present only in the intended
  environment files or secret stores.
- Runtime nodes point to the intended Plane environment, use the correct node
  pool, and have zero active executions before rollout.
- A verified production backup exists before a stateful deployment.

## Production Gate

Run the formal release gate documented in
[Production Deployment](/operations/production-deployment). Release is allowed
only when:

- Plane API regression passes
- Runtime lease failover passes
- every official package matrix case passes
- the production backup passes checksum and content verification
- external routing, authentication boundaries, and Compose health pass
- the cleanup dry-run is zero for every regression target

For frontend changes, also verify the rendered desktop and mobile flows, i18n,
loading/error states, primary interactions, and browser console health.

## Decision

Release only with no unresolved security, data-integrity, execution, billing,
or rollout blocker. Document target-specific exceptions before deployment; do
not weaken the shared gate or convert a failed mandatory check into an optional
one.
